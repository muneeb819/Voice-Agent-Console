# Repository audit and verification

Date: 2026-11-04. Scope: the Node/TypeScript console and bridge, static UI, speech-service fake runtime, launchers and release packaging. Tests used disposable data, synthetic credentials, local mocks and loopback ports; no customer systems, live provider keys or calls were used. The prior architectural document at `docs/AUDIT-REPORT.md` is historical, not the result of this review.

## Confirmed findings and remediation

| Priority | Finding and evidence | Change and verification |
| --- | --- | --- |
| Critical | Anonymous signup remained available with an admin password configured. A newly created account had full operator access; a local mock webhook demonstrated exfiltration of a **synthetic** admin secret through the existing interpolation feature. | Bootstrap is restricted to direct loopback and subsequent account creation requires a signed-in operator. `tests/security-verify.ts` covers bootstrap, closed anonymous signup, authorized signup and proxy boundaries. All accounts still have the same privileges; see risks. |
| High | A public IP was treated as loopback/trusted, explicit `127.*` bind/destination settings were rewritten, a bind failure could fall back to `0.0.0.0`, and forwarded headers could spoof login throttling or local PBX access. Admin bearer sessions remained valid after logout. | Loopback classification and destination preservation were corrected; listeners default to loopback and no longer widen on bind failure. Proxy headers require explicit trust, PBX exemptions require direct allowed peers, and admin sessions are uniquely issued and persistently revoked on logout. Security tests cover direct/proxied paths, spoofed headers, explicit hosts and revocation across processes. |
| High | With a synthetic session cookie, a request from `https://attacker.example` could log the user out (HTTP 200) and open a simulator WebSocket (101). Actual cross-site cookie delivery depends on browser/CHIPS behavior and was not demonstrated against a real TLS deployment. Local socket-only exemptions also allowed a non-loopback Host, creating a DNS-rebinding exposure. | Supplied HTTP and WebSocket origins must match the externally visible request origin, wildcard CORS was removed, cross-site pre-call browser requests are rejected, and loopback exemptions require a loopback Host. Regression tests cover synthetic cross-origin cookie HTTP/WS requests (now 403), same-origin requests, untrusted forwarded-host spoofing, trusted TLS proxy headers and rebound Hosts. Requests without `Origin` remain permitted for non-browser integrations. |
| High | Secret updates produced a world-readable `.env` (0644 in the reproduction), could corrupt quoted values or leave later duplicates that override updates. The old archive traversal included synthetic secret files; the download also returned 500 in that reproduction because its output was inside the archived tree. | Updates validate dotenv round-trips, reject injection, use atomic replacement with mode 0600 and remove duplicates. Release archives use an exact file manifest, reject symlinks and runtime/secret files, build outside the input tree and reject missing required files. Tests download and inspect a real archive from an isolated fixture, and verify excluded synthetic secrets, missing-file failure and manifest coverage. |
| High | Cancelling an in-flight speech job during shutdown deleted its source upload; recovery could also fail with `QueueFull` when running plus queued jobs exceeded queue capacity. | Cancellation preserves unfinished uploads and recovery feeds persisted jobs as workers make room. Two new tests verify interrupted-job completion, missing uploads and draining more jobs than the queue capacity using a fake runtime. |
| Medium | Sample-fetch failure silently returned a generated 440 Hz tone as a real voice sample. Dashboard quality/security values implied certification, while analytics counted only retained logs. | Network failures now return an explicit error; the UI reports unavailable audio. Quality is labeled a configuration estimate, certification is disabled, and analytics identify the 200 bridge / 100 simulator retained-call windows. Offline API and browser checks cover these states. |
| Medium | Mobile layout overflowed by 353 px at 390 px on the campaign view; the export view could grow by over 45,000 px due to min-content sizing. Wrapped header controls covered early navigation items. Some rendered inputs, including API key fields, lacked programmatic labels. | Responsive grid tracks can shrink, code blocks remain locally scrollable, and the rail tracks the actual header height. Labels were associated with rendered fields. Chromium checked all eight views at 320, 390 and 768 px with no document overflow; captured form fields all have a label, ARIA label, or title. This is not a complete accessibility audit. |
| Medium | Existing launcher/install defaults overwrote operator network settings, exposed hard-coded topology assumptions and advertised unauthenticated tunnels. Static-demo accounts could be mistaken for server authentication. The Python test dependency set initially reported known advisories. | Defaults are loopback-only, installer preserves an existing `.env`, public-tunnel launch checks authentication and local proxy readiness, and the static login explicitly warns that its accounts are browser-local. FastAPI, Starlette and multipart were upgraded; the resolved **test** requirements now have no known advisories. Deployment execution and full GPU dependency compatibility remain unverified. |

The iframe handoff token is removed from the address bar after the console loads and responses set `Referrer-Policy: no-referrer`; the initial handoff and WebSocket query URLs can still appear in server/proxy logs, and browser storage remains accessible to injected scripts.

## Verification performed

- `npm run build && npm test`: **48 groups passed** (13 step 1, 6 step 2, 9 step 3, 13 step 4, 7 security); one real Deepgram test was explicitly skipped. Protocol and telephony checks use mocks/local loopback, not a real provider or PBX.
- `.venv/bin/python -m pytest -q speech-service/tests`: **21 passed** against the fake runtime. Starlette emitted one `httpx` TestClient deprecation warning.
- `npm audit --audit-level=low`: no known vulnerabilities in the resolved Node lockfile. `pip check` passed and `pip-audit -r speech-service/requirements-test.txt` found no known vulnerabilities in the resolved test requirements. This is not an audit of the complete CUDA/GPU production image or future dependency resolutions.
- JavaScript and shell syntax, Python compilation, matching `public/` and `docs/` assets, and `git diff --check` passed. PowerShell was not available for execution or syntax validation.
- `audit/browser-smoke.cjs`: **22 checks passed**, no uncaught errors on the main page, and all **24** view/viewport combinations had zero horizontal document overflow. The isolated browser fixture blocks external HTTP requests and has no provider credentials. `audit/browser-results.json` contains 947 rendered control *instances* and 219 captured select options. Instances repeat shared controls across snapshots; modal snapshots include underlying page controls. Rendered/inventoried does **not** mean every button, option, keyboard path, destructive operation or integration was functionally exercised.

### Reproducing the browser smoke

From the repository root, build the project and install `playwright-core` plus a compatible Chromium separately (they are intentionally not project dependencies):

```sh
npm ci
npm run build
# Install playwright-core in an isolated location and provide a local Chromium.
npm install --prefix /tmp/vac-browser --no-save playwright-core
NODE_PATH=/tmp/vac-browser/node_modules BROWSER_EXECUTABLE=/path/to/chromium \
  node audit/browser-smoke.cjs
```

The script writes `audit/browser-results.json`, creates a temporary data directory and test-only `.env`, launches a loopback server and uses synthetic passwords. It exercises login, authenticated account creation, logout/sign-in, agent edit/discard/save/reload, theme/exposure and API-key modals, eight navigation views, unavailable audio/simulator messages, retained analytics, responsive navigation and the static-demo warning. It does not exercise real microphones, audio playback, destructive production actions, all theme/provider options or screen readers. Chromium may require additional system libraries; no browser binary is committed.

## Remaining risks and operational follow-up

1. **Privilege separation is absent.** Every authenticated account is a full operator, can create other operators and can configure/test webhooks with secret interpolation. Limit access to trusted operators and egress; implement roles, authorization and stronger webhook/SSRF restrictions before a multi-tenant deployment.
2. Session bearer tokens are held in browser storage and passed in initial handoff / WebSocket query strings for cookie-less iframes. XSS, browser extensions, access logs or proxy logs can expose them. Use a restrictive CSP, avoid logging query strings, protect endpoints and consider short-lived single-use handoffs and WebSocket tickets.
3. Origin defenses intentionally allow requests without an `Origin` for non-browser PBX/API clients; this is not a token-based CSRF guarantee for legacy clients. Use HTTPS, restrict network access and trust only reverse proxies that overwrite forwarded headers. Configure `TRUST_PROXY` accurately; a local cloudflared tunnel needs its local proxy address trusted and will now refuse to launch if the readiness probe fails. Real TLS, embedded-iframe and cloudflared behavior were not tested here.
4. The installed systemd service, Docker/Render images, PowerShell scripts, real Deepgram/other provider APIs, real VICIdial/Asterisk/AMI, remote SIP/RTP, microphone permissions, GPU inference and Chatterbox cloning were not tested. The Windows helpers probe the configured port on IPv4 loopback and may need adaptation for a listener bound only to a non-loopback address. The historical ViciBox runbook contains environment-specific topology examples; validate a staging deployment before production.
5. Production dependencies, model downloads, available GPU drivers, operating-system package availability and the release archive's `tar` implementation on Windows were not audited. The installer still relies on external package sources and was not run with elevated privileges.
